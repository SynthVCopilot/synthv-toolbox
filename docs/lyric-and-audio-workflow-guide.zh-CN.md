# Toolbox 创作工作流与设计

Toolbox 的本地创作主流程是：准备素材 → 导入旋律 → 写词与版本管理 → 预览并写回 SynthV → 保存、渲染与导出。SynthV 是当前工程的唯一事实来源；Toolbox 管理草稿、文件产物、历史和检查点。

## 工作区与步骤

| 入口 | 输入 | 产物与完成条件 |
| --- | --- | --- |
| 导入 · 曲谱导入 SynthV | 本地 MIDI / MusicXML / MXL | 新音符组；有权限确认、文件指纹和新鲜写入 Context；不自动改变工程速度 |
| 转换 · 音频准备 | 本地音频 | 用户确认参数后生成独立 PCM WAV；显示实际文件和可播放的产物 |
| 转换 · 演唱音频 → MIDI / SynthV | 演唱音频，可选同时间轴伴奏 | 单声部 MIDI；可接 Bridge 导入。此入口不自动识词，歌词在作词页填入 |
| 作词 | 草稿、段落结构、韵脚目标 | 本地项目、明确保存的版本、TXT；选区歌词写入有预览和确认 |
| 转换 · SV 工程文件 | SynthV 已保存的 SVP | 结构探测、无参副本、静音参考轨副本、普通及逐字 LRC |
| 分析 · 音频结构分析 | 本地音频 | BPM、调性和音频特征；估计值用于参考 |
| 质检 | SVP、歌词或渲染音频 | 工程/歌词结构/音频报告，可导出 Markdown 或 JSON |
| 质检 · 批处理 | 最多 100 个本地文件 | 串行处理，每个文件独立报告成功或失败 |
| 历史 | 上述本地工作流 | 输出路径、结果摘要、检查点和恢复为新文件 |
| Copilot | 用户指令、已配置的模型 | 复用同一个内嵌 Bridge；高风险修改按工作模式审批 |

基础工作流不要求模型账号。AI 建议不会自动成为正式歌词。用户可以在 Copilot 中取得建议，回到草稿中采用和修订。

## 从素材到成品

1. 有 MIDI 或 MusicXML 时，从“导入”选择目标轨道、音符组名称并确认素材使用权限。当前每次导入最多 512 个单声部音符；多声部、重叠或不明确的声部选择会报错。
2. 只有演唱音频时，先用“音频准备”检查文件并按需转换，再用“演唱音频 → MIDI / SynthV”提取旋律。伴奏可留空。低置信结果应在 SynthV 中人工试听和修正。
3. 在“作词”输入歌名与草稿，按需插入段落模板或查询中文韵脚。“保存”生成项目修订；键入时的临时草稿自动保存与项目版本是两个动作。
4. 在 SynthV 选择需要填词的音符，回到“作词”读取选区。选择草稿文字逐字填入，或单独编辑每个词槽。预览中的新旧歌词正确后确认写回。
5. Toolbox 回读歌词、音高和时值，只有验证通过才报告写入完成。随后在 SynthV 保存工程、选择声库并试听或渲染。
6. 用“SV 工程文件”导出 LRC、逐字 LRC或工程副本；用“质检”检查保存的工程与渲染音频，并导出报告。

中文逐字填词要求字符数量等于选中音符数。延音、连读或其他语言可在词槽中明确处理；工具不自行改变音高、时值或语言。

## 数据与持久化

创作数据保存在 Electron 用户数据目录的 `creative/` 下：

- `lyrics/projects.json`：歌词项目、段落、韵脚目标、候选记录与历史版本。
- `lyrics/exports/`：独立 UTF-8 TXT，每次导出使用新文件名。
- `creative-history/entries.json`：最近 200 条完成的工作流记录。
- `project-checkpoints/`：处理过的 SVP 内容副本及 SHA-256、长度和来源索引。
- `output/`：本地组件生成的 MIDI、LRC 和 SVP 副本。
- `reports/`：完整 Markdown 或 JSON 报告。

FFmpeg 的受管 WAV 位于用户数据目录的 `components/audio-output/`。用户明确选择的 MIDI 输出目录属于例外，仍采用新文件且拒绝覆盖。

项目保存通过串行队列和原子替换完成。旧稿最多保留 30 个版本，候选最多 20 组；单项目 16 MiB、项目库 64 MiB。只裁当前项目最旧的历史；当前内容或项目库仍超限时，保存失败并保留上次有效文件。

本次会话处理过的 SVP 会建立内容去重检查点，并每 60 秒检查已保存文件的变化；未保存的宿主编辑不在文件备份范围内。恢复前验证快照哈希，只恢复到新的同目录 SVP，拒绝覆盖任何现有文件。关闭 Toolbox 后不继续后台扫描文件。

## 写入与失败语义

- 内嵌 Bridge 是唯一写入通道；桌面工具与 Copilot 复用该实例。
- 选区读取和预览令牌有效期两分钟。切换工程会话、改变选区、修改音符或令牌过期时必须重新读取。
- 预览本身不写入。确认令牌使用一次即失效；实际写入使用同组的 `writeIntent` Context 和宿主指纹。
- 共享音符组默认拒绝改写。一个歌词操作保持一个宿主撤销边界。
- 写后回读失败会明确提示“已写入但验证失败”，要求检查宿主；不会自动重试写入。
- 同步本地工作流直接返回 `kind / summary / data / outputPath`。失败抛出具体错误，不返回“完成”任务外壳。
- 原文件保持不变。受管目录限制真实路径，拒绝目录穿越、逃逸符号链接和已有输出。

## 组件与硬件

Electron 保持硬件加速默认启用。Basic Pitch 默认按本机 ONNX Runtime 可用 provider 选择硬件：macOS 为 CoreML，Windows 优先 CUDA、其次 DirectML，其他平台优先 CUDA。CPU provider 执行硬件不支持的节点；运行错误不会被静默转换为全 CPU 成功。

音频结果的 `inference` 字段报告请求与实际启用的 provider。`hardwareEnabled` 表示会话启用了硬件 provider，不代表每个算子都在硬件上运行。测试可显式设置 `SYNTHV_TOOLBOX_INFERENCE_DEVICE=cpu`。

组件脚本随应用分发，但音频 Python 依赖和 FFmpeg 需要本机运行环境。可用 `SYNTHV_TOOLBOX_PYTHON` 指定含组件依赖的 Python 3.11；依赖清单位于 `components/pi-audio/requirements.txt`。缺失依赖时应安装对应运行环境，不能把“脚本已打包”当作全部模型已安装。

韵脚查询使用 pinyin-pro 的字典读音，覆盖 U+3400–U+9FFF 范围内的已收录汉字，多音字按收录读音匹配。它提供韵脚提示，不评判文学质量。发音诊断检查文字、音符与结构风险，不等于声学发音或艺术质量验收。

## 后续模块的完整边界

以下模块尚未完成 Electron 可运行实现，默认不作为已就绪工具展示：平台音频导入、一键 Cover、人声分离编排、分声库调声学习、系统回环 A/B 捕获。已有脚本或旧界面不能作为这些功能完成的证据。

平台导入的确定流程为：用户提供单个 URL → 预览元数据 → 确认素材权限 → 下载到受管暂存目录 → FFmpeg 标准化 → 内容哈希与来源记录 → 接入本地创作主流程。队列应持久化，支持取消、失败重试和重启后恢复；未校验的半成品不能成为可用素材。站点解析采用独立、固定版本和校验和的 yt-dlp 组件，不接管用户登录态。

Cover 必须复用导入、分离、旋律提取、歌词对齐和 Bridge 的明确步骤，逐阶段保留输入、输出和错误。调声学习必须先保存真实参考特征，再按宿主实际可用范围生成候选；用户试听和 A/B 结果属于验收输入，不能凭样本计数宣称已经学习。A/B 捕获需具备对应 OS 的真实捕获组件和延迟对齐验证。

歌曲项目后续扩展沿用当前项目标识，关联来源、旋律文件、草稿版本、工程检查点和导出清单。大型媒体由内容哈希引用；删除项目索引与删除受管媒体是不同操作，用户原始素材不属于删除范围。

## 验证方式

在 `src/PiDesktop.Tauri` 中使用现有 npm 锁文件：

```sh
npm ci
npm run build:electron
npm run test:contracts
npm run test:creative-workflow
npm run test:usability
npm run test:bridge-lyrics
npm run test:midi
npm run test:electron-app
```

真实验收还需要可运行的 SynthV 和声库：用独立素材完成导入、选区填词、保存、渲染，再读取实际 SVP/WAV/LRC。测试替身只能证明协议和保护行为，不能代替真实宿主或音频产物。
