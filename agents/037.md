# 过期会话续期链路

- 用户明确要求发现 access token 过期后先 refresh 再读取授权，不能停在过期提示。
- 空闲批量分支已有续期，但活动分支提前返回 Expired；且旧隔离在最终结果合成时可能覆盖最新 HTTP 失败原因。
- 在单份物理会话约束下复用标准 refresh→身份校验→原子写回→新 token 查询链路，保留源文件变化时不覆盖的边界；是否有运行实例只影响展示，不禁止续期。
- 用合成端点/会话验证调用顺序、仅一次 refresh、刷新失败不访问授权、不暴露凭据和并发修改保护；不扩大账号权限、不踢出其他会话。
- 延续 Windows worktree 既有目录；子 agent 有界实现，主工作区审查传输与实际端到端行为，最终按 main 保护状态提交交付。
- 普通 HTTP 403 不证明 access token 失效，只有 401 或明确的重新登录错误触发一次续期；遵循 RFC 6750 的认证失败/权限不足区分。
- 隔离期间保留最新预检失败，创建新隔离时清掉旧结果；成功读取同一稳定会话的授权后清除隔离，避免三秒 TTL 后重新展示更旧的失败。
