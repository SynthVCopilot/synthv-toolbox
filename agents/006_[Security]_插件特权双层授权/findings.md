# 技术调研

- 现有插件只保存启停状态，插件声明权限后即可请求对应宿主能力。
- GUI 沙箱能隔离插件页面，但真正权限边界位于 Rust 的 `host.capability.invoke` 处理器。
- 新授权需要同时满足 manifest 声明、应用全局开关、插件独立开关，任一关闭都必须由宿主拒绝。
- 插件安装状态位于每个插件目录的 `.toolbox-plugin-state.json`；将其扩展为两个默认关闭的布尔值，令 UI 与宿主读取同一状态。
- 当前调用协议虽然由运行时附带插件标识，但 Rust 端未反序列化该字段；必须在宿主重新读取已安装 manifest 和持久化状态，不能信任运行时的权限声明。
- `reqwest` 的地址解析覆盖可固定到已验证的公网地址；联网能力只接受 HTTPS，拒绝包含任意私有、回环、链路本地或保留地址的解析结果，并禁用重定向。
