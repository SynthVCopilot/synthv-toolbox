# 会话修复与实例操作

- 用户反馈最终构建仍然所有槽位显示会话同步失败，并将安装程序列为 SynthV 实例；要求简洁的版本、账号、工程名与切换到/终止操作。
- 先读取本机受管目录的结构和脱敏状态，禁止输出令牌或把真实账号信息写入仓库。复现必须覆盖实际失败条件，不能只改提示。
- 三个独立 worktree 分别处理授权探测、进程识别与控制、实例界面；主工作区负责真实状态调查、槽位编排与集成。
- 保留同账号同环境多进程和每账号一份数据。默认不显示磁盘路径；终止仅作用于校验后的目标进程。
- Windows worktree 使用既有 C:/Users/User/.codex/worktrees/pi-desktop 专属位置。保持既有 worktree 不动，最终本地合并 main，按保护状态交付。
- 实际故障是有效 access token 被强制 refresh、固定 client ID 与原会话不符、远端 Cloudflare 403 被归入可能轮换并进入永久隔离。优先使用官方只读授权接口；保留真正不确定轮换时的保护，不能通过取消所有校验掩盖问题。
- 用户追加火绒误报调查。构建工具的有效签名、正常源码和标准编译链仅支持疑似误报，不能证明已删除样本安全。不存在有依据的冗余注入调用；保留必要实例控制，不做混淆、改名、改哈希、白名单或关闭防护。当前发布程序未签名，签名属于后续需真实证书支持的发布身份改进，不能虚构证书或替代厂商复核。
