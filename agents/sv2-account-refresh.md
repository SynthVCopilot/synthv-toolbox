# SV2 账号按槽位刷新与识别状态保留

## 现象

- 本地会话可以解出账号姓名与邮箱，但账号卡统一显示会话同步失败。
- 切换默认槽位后，前端使用基础槽位状态覆盖探测快照，导致姓名、邮箱、占用与授权结果回到未检查状态。
- 用户需要只刷新单个账号，避免一次手工操作探测所有账号。

## 诊断记录

- 只检查了本地清单、会话文件是否存在、时间、长度、摘要和文件占用；未输出或保存 JWT、明文 session、token 或其他 claims。
- 普通与隔离目录是普通物理目录，不是重解析点；已有隔离 session 文件可用删除共享方式打开，没有发现统一的文件锁或权限阻断。
- 有一个已准备的隔离环境缺少 session；其他隔离副本与普通副本内容和更新时间不同，需要通过同一次账号预检收敛。
- 会话原子替换向 `ReplaceFileW` 传入了文档明确标为不受支持的写穿标志。该调用改用受支持的零标志；刷新后仍失败时，界面会展示后端返回的具体失败原因。

## 决策

- 单账号刷新仍同时处理该槽位现存的普通与隔离副本，二者共享一份刷新权威，不允许各自轮换。
- 未选中的槽位只读取进程内清洗后的缓存，不解密 session，也不调用账号服务。
- 基础槽位状态重建时恢复相同 session 指纹的清洗缓存；缓存过期时仅保留姓名和邮箱，指纹变化时不继承旧账号身份。
- 客户端正在使用会话时仅显示同槽位上次脱敏姓名和邮箱，状态固定为本机使用中且授权未知，不复用旧的可启动结论。
- 敏感刷新入口仍仅来自开启确认、进入账号页、全局手动刷新和单账号手动刷新。
- 不增加轮询、后台定时刷新或新的持久身份存储。

## 验证

- `cargo fmt --check`、`cargo check` 和 `cargo clippy --all-targets -- -D warnings` 通过。
- Rust 完整测试通过：140 通过、1 忽略、0 失败。
- TypeScript 编译及 Vite 构建通过。
- 根目录契约测试通过，确认单账号命令端到端注册、切换状态恢复缓存，并禁止再次传入不受支持的替换标志。
